# Requirements-analysis knowledge index

Use this index only after the user has confirmed the workbench selection. Load
the smallest set of references that changes the analysis. The references supply
methods and review questions; they are not evidence about the user's project.

## Routing

| Scenario signal or confirmed module | Read |
|---|---|
| Unclear problem, symptoms, root causes, vocabulary, scope, system boundary, feasibility, vision, `problem-vision-scope`, `fishbone`, `context`, `domain-model`, or `feasibility` | [Problem framing and domain models](knowledge/problem-framing-and-domain-models.md) |
| Functional, quality, business, acceptance, ambiguity, SRS, or traceability concerns; always when `requirements` is selected | [Requirement quality and traceability](knowledge/requirement-quality-and-traceability.md) |
| Actors, personas, user stories, scenarios, use cases, processes, interfaces, data input/output, `use-cases`, `activity`, `wireframe`, or `data-io` | [Stakeholders and behavioural models](knowledge/stakeholders-and-behavioural-models.md) |
| Lifecycle choice, prototyping, constraints, trade-offs, roadmap, backlog, handoff, acceptance testing, sign-off, or `lifecycle-roadmap` | [Delivery planning and handoff](knowledge/delivery-planning-and-handoff.md) |

Read more than one reference when the scenario crosses these boundaries. Do not
force every technique into every analysis, create facts absent from supplied
sources, or turn a useful model into an unsupported implementation decision.

## Shared invariants

- Stay in the problem domain until the problem, affected stakeholders, causes,
  vocabulary, and boundary are sufficiently clear.
- Keep explicit statements, inferences, proposals, conflicts, and open questions
  visibly distinct.
- Treat diagrams and prototypes as models for learning and review, not as proof
  that the model is complete or correct.
- Keep requirements, models, tasks, tests, and approvals traceable with stable
  identifiers and versioned artefacts.
- Revisit models when new evidence changes the domain understanding.

This knowledge base is a concise synthesis of requirements-analysis teaching
material. Source-specific wording, decorative media, and course-only rules are
intentionally excluded from the reusable plugin.
